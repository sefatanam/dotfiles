This page is partly generated. Six regions are rewritten from the tracked configs by ./update-keybindings.sh; everything outside the fences is hand-written. Run ./update-keybindings.sh --check to verify it is current (./setup-validate.sh does this for you).

Terms like leader, prefix, mode and chord are defined in CONTEXT.md. Two things to know before reading the tables:

  • Some rows are marked inherited rather than declared. Those work because tmux ships them by default, not because this repo configures them — see Gotchas.

Gotchas

  • Cmd+B in Ghostty depends on a tmux default, not on this repo. It sends the raw sequence \x01\x7a, i.e. prefix then z. z is never bound in tmux/.tmux.conf, so it resolves to tmux's built-in default resize-pane -Z — “toggle zoom state of the current pane”. That works today, but it is the one key here that depends on tmux's defaults rather than on anything in this repo: rebind z or upgrade tmux and Cmd+B stops zooming with no error in Ghostty's config to explain why. It is the reason prefix+z is marked inherited in the tmux table.
  • Cmd+S is likewise a raw sequence, not a save. \x01\x73 is prefix then s, which tmux binds to split-window -v. So Cmd+S splits panes, while Cmd+Q (not bound here) would be the actual save.
  • tmux's split flags read backwards from what they produce. split-window -h — used by prefix+v and prefix+% — puts panes side by side. split-window -v — used by prefix+s and prefix+' — stacks them. The flag names the direction of the split operation, not the arrangement you end up looking at.
  • Neovim's Space is the leader, and is also remapped to nothing. nvim/lua/config/customize.lua sets vim.g.mapleader = " " and maps <Space> to an empty right-hand side, so a bare Space is the leader prefix rather than an insert-mode space.
  • The prefix+Ctrl+r yazi popup is dead. tmux/.tmux.conf binds C-r to a yazi popup at line 133, but the same file loads tpm at line 274, and tmux-resurrect binds C-r to its restore script when it loads — after the config's own binding. The plugin wins, so prefix+Ctrl+r restores a session rather than opening a file picker, and yazi is not reachable from any binding. tmux -f ~/.tmux.conf list-keys -T prefix shows the effective binding, which is how this was found; the config file alone still claims yazi. Rebinding C-r after the tpm line, or moving yazi to an unbound key, would fix it — left alone here because this repo only documents its configuration.
  • Two of the six sources are single-binding files. Alacritty and zsh each declare exactly one binding. Their tables being this short is accurate, not a parsing failure — the generator skips and warns rather than emitting a truncated table if a source ever becomes unreadable.
